## Risk Coverage

- **DATA-001**: Schema corruption → UNIT-001 through UNIT-004
- **DATA-002**: Referential integrity failures → INT-008, INT-009
- **SECURITY-001**: Unauthorized data access → INT-004, INT-005, INT-006
- **BUSINESS-001**: Ticket code generation failures → UNIT-005, INT-001, INT-002
- **MIGRATION-001**: Database evolution failures → E2E-001, E2E-002, INT-007
- **LOCALE-001**: Vietnamese data handling → INT-011, INT-012

## Test Implementation Guidelines

### Unit Tests
- Use isolated test database instances
- Mock external dependencies (auth service)
- Test individual functions and constraints
- Validate schema structure and data types

### Integration Tests
- Use test containers with full PostgreSQL setup
- Test actual database operations and constraints
- Verify RLS policies with real user contexts
- Include Vietnamese test data for localization testing

### E2E Tests
- Full migration workflow testing
- Performance testing with realistic data volumes
- Complete database lifecycle validation
- Include migration rollback scenarios

## Test Data Requirements

### Vietnamese Test Data
- Customer names with Vietnamese characters (Nguyễn, Trần, etc.)
- Phone numbers in Vietnamese format (09XXXXXXXX, 08XXXXXXXX)
- Repair descriptions with Vietnamese technical terms
- Test timezone scenarios with Asia/Ho_Chi_Minh

### Business Logic Test Data
- Multiple ticket creation scenarios across years
- User registration with various role combinations
- Complex repair workflows with status transitions
- Parts inventory with Vietnamese product names

## Notes for Implementation

- All tests must handle UTF-8 Vietnamese characters correctly
- RLS policy tests require multiple user contexts
- Migration tests need clean database setup/teardown
- Performance tests should use realistic data volumes (1000+ records)
- Include error scenarios for constraint violations
- Document expected Vietnamese collation behavior
